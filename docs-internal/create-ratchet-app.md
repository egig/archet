# `createRatchetApp` — one server-assembly function

> Status: implemented. This doc is the design of record; see `src/server/`, `.ratchet/app.ts`
> codegen, and `test/server.test.ts`.


## Problem

The registration-order-sensitive route-mounting sequence is duplicated in four places
and has already drifted:

| Site | `/api/auth` | `/api/automation` | `/api` | console | `/_site-assets` | web | storage |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `src/cli/commands/serve.ts` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ everywhere |
| generated `server-entry.ts` (`build-console.ts`) | ✅ | ❌ | ✅ | ✅ | ❌ | ✅ | ❌ |
| `example/deploy/cloudflare/worker.ts` | ✅ | ❌ | ✅ | ✅ | ❌ | ❌ | api only |
| `example/deploy/vercel/api/index.ts` | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ | api only |

Consumers deploying to Workers/Vercel copy ~180 lines and get an out-of-date wiring
sequence. Adding a router (as `/api/automation` and `/_site-assets` both were) silently
misses three of the four sites.

## Solution

A single assembly function `createRatchetApp` that owns the canonical sequence. Every
entry point — `serve`, the built Node bundle, a Worker, a Vercel function — calls it
with already-constructed infrastructure (`db`, `storage`, console asset source) and the
generated model/domain bundle. It does no config loading and no dynamic import of
generated files, so it runs unchanged inside a Worker's `fetch(request, env)` handler.

### `@egig/ratchet/server` — `src/server/index.ts`

```ts
async function createRatchetApp(opts: RatchetAppOptions): Promise<App>

interface RatchetBundle {
  models: Record<string, ModelDefinition>;
  domains: Record<string, DomainDefinition>;
  web?: { routes: RouteObject[]; resourceRouteIds?: ReadonlySet<string> };
}

interface RatchetAppOptions {
  db;                                   // infra, required
  bundle: RatchetBundle;                // generated barrel, required
  storage?;                             // infra — omit → file-field writes 500 (unchanged today)
  consoleAssets?: ConsoleAssetSource;   // infra — omit → console router not mounted
  consolePath?: string;                 // default '/console'; validated when consoleAssets set
  web?: { entrySrc: string; publicDir?: string; generatedDir: string };
                                        // required iff bundle.web present, else throws
}
```

Behaviour:

- **Always mounted, fixed order:** `/api/auth` → `/api/automation` → `/api` →
  `/_site-assets` → *(console)* → *(`/_ratchet` + web `/`)*. `/_site-assets` now sits
  **before** the console (it was after, in `serve.ts`): its fixed 3-segment prefix can't
  shadow the console, and mounting it first means a `consolePath: '/'` no longer swallows
  public asset URLs — a latent-bug fix folded in.
- `webEntry` in the table above is the `web?:` option key; `entrySrc` fills a `<script
  src>`, `generatedDir` locates `<generatedDir>/web/assets` for `/_ratchet/*`.
- **Features are always on. Only infrastructure is configurable.** Console mounts iff
  `consoleAssets` is supplied ("did you give me somewhere to read built JS/CSS from" —
  Vercel serves those off its CDN and passes nothing). Web mounts iff `opts.web` is
  supplied (its runtime paths — `entrySrc`, `generatedDir`, `publicDir` — aren't in the
  bundle); a caller that omits it (a Vercel function fielding only `/api/*`, site
  deployed separately) just doesn't get the `/` + `/_ratchet` mounts. Supplying
  `opts.web` when `bundle.web` is absent (no `routes/root.tsx`) throws — you asked to
  mount a site codegen never produced.
- **`async` + lazy sub-imports.** `auth` / `automation` / `api` / `site-assets` are
  statically imported (always mounted anyway). `../console/router.js` is
  `await import()`ed only when `consoleAssets` is set; `../web/router.js` only when
  `bundle.web` is present. Keeps React Router + console client bits out of a
  Vercel/Worker module graph that never mounts them. Per-request in a Worker the dynamic
  import resolves from module cache after the first hit.
- **`consolePath` validation** shared with `load-config.ts` — extracted to
  `src/server/console-path.ts` (`assertValidConsolePath`): must start with `/`, no
  trailing slash, no `/api` collision. `createRatchetApp` runs it (catches the
  hardcoded-`CONSOLE_PATH`-typo case the Worker file only warns about in a comment);
  `resolveConsolePath` in `load-config.ts` calls the same function.
- Pure assembly: returns `Promise<App>`. Listening (`Bun.serve` / `serveNode` /
  `export default`) and logging stay in each caller.

### Generated barrel — `.ratchet/app.ts`

`ratchet generate` writes it alongside `registry.ts` / `domains.ts` (new
`generateAppBundleSource` in `src/codegen/`, called from `generate.ts`):

```ts
// GENERATED by `ratchet generate` — do not edit.
import * as registryModule from './registry.js';
import * as domainsModule from './domains.js';
import { buildRegistryMap, buildDomainSettingsRegistryMap } from '@egig/ratchet/router';
import { routes, resourceRouteIds } from './app-routes.server.js';   // only when web opted in

export const bundle = {
  models: buildRegistryMap(registryModule as Record<string, unknown>),
  domains: buildDomainSettingsRegistryMap(domainsModule as Record<string, unknown>),
  web: { routes, resourceRouteIds },                                  // only when web opted in
};
```

One `import { bundle } from './.ratchet/app.js'` replaces the two `import * as` lines +
two `build*Map()` calls every entry point does today. No keyspace merge — `models` and
`domains` stay separate maps, just carried in one object.

### Migrated call sites

- **`src/cli/commands/serve.ts`** → load config, build `db` / `storage`, dynamic-import
  `.ratchet/app.ts`, `await createRatchetApp({ … })`, `Bun.serve`. ~15 lines.
- **`src/cli/build-console.ts`** (`buildServerBundle`) → emit a trivial `server-entry.ts`
  that imports `./app.js`, calls `createRatchetApp`, `serveNode`. Still bundled to
  `dist/server.js`.
- **`src/cli/commands/dev.ts`** → untouched (spawns `serve` as a crash-isolation child).
- **`serve` command** → kept. It is not the maintenance burden; the duplicated wiring
  was.

### User-owned, documentation only (not shipped as framework code)

- **`example/deploy/cloudflare/worker.ts`** → rewritten against `createRatchetApp`. The
  R2 `StorageAdapter` and the `env.ASSETS` → `ConsoleAssetSource` adapter stay
  copy-paste in this file (per decision: ship implementation docs, not a
  `@egig/ratchet/cloudflare` package). Mounting collapses to one `createRatchetApp` call
  per request.
- **`example/deploy/vercel/api/index.ts`** → rewritten against `createRatchetApp`; loses
  the manual `app.route` pair.
- Both wired into `bun run typecheck` via a dedicated `example/deploy/tsconfig.json`
  (`extends` root, adds `allowImportingTsExtensions` + `noEmit` — the generated
  `app.ts` → `app-routes.server.ts` chain imports `.tsx` route modules by extension,
  legal at runtime but not for plain `tsc`). Root `tsconfig.json` now `exclude`s
  `example/deploy`; the `typecheck` script runs both projects.
- **`docs/content/docs/deploy.mdx`** → rewrite all three sections (VPS / Vercel /
  Cloudflare) around `createRatchetApp`.
- **`docs/content/docs/router.mdx`** → short "assembling a server" note pointing at
  `createRatchetApp` (`App` / `createApiRouter` stay exported for the à la carte path).
- **`CHANGELOG.md`** `[Unreleased]` → `Added: @egig/ratchet/server / createRatchetApp`.
  **Not** marked `Breaking:` — the old `App` + `createApiRouter` composition still works;
  this is additive.
- No new ADR — implementation consolidation, not a design-principle decision.

### Tests — `test/server.test.ts`

No `DATABASE_URL` (stub `db`):

- `createRatchetApp({ db, bundle })` → `/api/auth/me`, `/api/automation/*`,
  `/api/:model`, `/_site-assets/*` all resolve (not 404); console path 404s
  (no `consoleAssets`).
- With `consoleAssets` → console path resolves.
- Registration order: `consolePath: '/'` still lets `/api/...` and `/_site-assets/...`
  win (the shadowing contract currently guarded only by a comment).
- Bad `consolePath` (`/api/x`, `foo`, `/x/`) → throws.
- `opts.web` supplied while `bundle.web` absent → throws. `bundle.web` present while
  `opts.web` absent → no `/` mount, no throw (API-only deploy).

### `package.json`

Add `"./server": "./dist/server/index.js"` to `exports`. `scripts/build.ts` globs
`src/` unbundled, so `src/server/` is picked up automatically; `tsc` emits the `.d.ts`.

## Out of scope (possible follow-ups)

- Static framework-shipped Node entry replacing the generated `server-entry.ts`
  (needs `ratchet build` to write the hashed web `entrySrc` into a manifest the static
  entry can read).
- Shipping `@egig/ratchet/cloudflare` / `@egig/ratchet/vercel` with the storage/asset
  glue.
- Refactoring routers to request-scoped `db` (would let a Worker build the `App` once).
