# Domain membership is inferred from folder structure

We needed a way to group related Models into a Domain (e.g. `auth`). The alternative was an explicit `domain: 'auth'` field on `ConsoleModelOptions`, letting a Model declare its Domain independent of where its file lives. We chose folder inference instead: a Model's Domain is the top-level subdirectory it's declared in under `modelsDir` (`models/auth/user.model.ts` → domain `auth`), with no subdirectory meaning no Domain. This piggybacks on the existing recursive `scanModels()` walk (`src/codegen/scan.ts`) rather than adding a new declared property, and forces one Domain per Model instead of letting the two drift apart. Framework built-ins (`src/auth/models`) aren't reachable by this scan, so `BUILTIN_MODELS` (`src/codegen/builtins.ts`) assigns their Domain explicitly as a special case, same as it already special-cases their import path.
